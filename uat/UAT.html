1) How to run UAT (Runbook)

Critical demo constraint: This app persists data in browser localStorage. Collaboration is a workflow simulation, so you must test multi-user flows by switching users in the same browser profile.

1.1 What you are testing (one line)

A collaborative principle-authoring and review workspace: search/read/save principles, propose new principles via Draft → Collaborate → Submit, manage collaboration via Inbox + Timeline, and review via Moderator/Admin.

1.2 UAT preparation checklist

  • Confirm the Vercel URL to test (paste it into the “Environment” field in your first test case).
  • Use Chrome or Edge.
  • Have a folder ready for screenshots (evidence).
  • Plan to run in one browser profile (avoid mixing Incognito and normal windows).

1.3 How to generate the PDF deliverable

  1. Open this file (uat/UAT.html) in Chrome/Edge.
  2. Press Ctrl+P (Print).
  3. Destination: Save as PDF.
  4. Enable Background graphics (recommended).
  5. Save as: STOD-UAT-<date>.pdf.

3) Reset & troubleshooting

3.1 Soft reset (recommended first)

  • Logout
  • Refresh
  • Login again

3.2 Hard reset (clears demo data in this browser)

When to use: You want a clean run, or the demo data got inconsistent during testing.
  1. Open DevTools (F12)
  2. Go to Application
  3. Left side: Storage → Local Storage → select the app origin
  4. Delete these keys if present:
stod_user
stod_users
stod_principles
stod_principles_seed_version
stod_hidden_principles_by_user
stod_principle_drafts
stod_notifications_by_user
stod_principle_annotations
stod_videos
stod_sessions
stod_bookings
stod_forums
  1. Refresh the page
Expected: App returns to clean seeded state.

3.3 Common UAT issues

  • “I don’t see the invite / draft / notification”: refresh once; confirm you are using the same browser profile; confirm you are signed in as the correct user.
  • “It opened on a random page earlier”: the app should always land on Home; if it doesn’t, capture a screenshot and report as a defect.

4) Persona packs (role-based UAT)

Rule for collaboration UAT: When a script says “switch user”, do Logout then login as the next user. Do not open a new browser, unless you intentionally want a separate clean data store.

4.1 Non-subscriber pack (Nina)

NS-01 Sign in as Non-subscriber
Role: Non-subscriber • Area: Auth/Nav

Steps

  1. From Home, click Sign In.
  2. Login as non / non123.

Expected results

  • Dashboard loads.
  • Role indicator shows Non-subscriber.
  • Tools and Collaborate appear locked/disabled.
NS-02 Search and open allowed (featured) principles
Role: Non-subscriber • Area: Search/Reader

Steps

  1. Go to Search.
  2. Open a featured principle card (or one that is not locked).

Expected results

  • Principle opens in Advanced Reader.
NS-03 Attempt to open a locked principle (upsell modal)
Role: Non-subscriber • Area: Gating/Upsell

Steps

  1. In Search, click a card that appears locked (or triggers an unlock prompt).
  2. In the unlock modal, read the messaging.
  3. (Optional) Click “Become Subscriber” (demo) to validate the upgrade path.

Expected results

  • An unlock/upsell modal appears.
  • Upgrade path changes role locally and unlocks access.

4.2 Subscriber pack (Sam/Sid/Sana)

Primary validation areas: drafts workflow, collaboration (invites/requests), suggestions + comments, watch/unwatch, Inbox notifications, timeline drawer behavior, and submission to Moderator review.
SUB-01 Sign in as Subscriber (Sam)
Role: Subscriber • Area: Auth/Nav

Steps

  1. Logout (if needed).
  2. Login as subscriber1 / subscriber123.

Expected results

  • Collaborate is enabled.
  • Inbox is available.
  • Review is hidden (Subscriber does not review).
SUB-02 Create a draft (Owner)
Role: Subscriber • Area: Propose/Draft

Steps

  1. Go to Propose.
  2. Create a new draft.
  3. Fill the fields (title, category, description, take-home, full text, hard questions).
  4. Save/confirm the draft exists in “My drafts”.

Expected results

  • A new draft is created and is selectable.
  • Owner edits appear in the Activity timeline.
SUB-03 Timeline drawer open/close reliability
Role: Subscriber • Area: Timeline UX

Steps

  1. Open the draft workspace.
  2. Click Timeline to open the drawer.
  3. Close via X.
  4. Open again; close by clicking the backdrop.
  5. Open again; close with Esc.

Expected results

  • Timeline drawer opens and closes reliably by all methods.
  • It closes (does not “shift” or partially remain on screen).
SUB-04 Open draft to collaborator requests
Role: Subscriber • Area: Collaboration setup

Steps

  1. As Sam (owner), in the draft workspace enable: Open this draft to collaborator requests.
  2. Note the exact draft title (you will look for it in Collaborate as other users).

Expected results

  • The draft is marked open for requests and will appear in Collaborate → Open drafts for other subscribers.
SUB-05 Invite a subscriber (Sam invites Sid)
Role: Subscriber • Area: Invites/Inbox

Steps

  1. As Sam (owner), open the draft and go to the Collaborate stage (inside the draft workflow).
  2. In “Invite a subscriber”, select Sid Subscriber 2.
  3. Click Invite.

Expected results

  • Sid receives an Invite received notification in Inbox.
  • Sid sees the draft under Collaborate → Invited.
SUB-06 Switch user and accept invite (Sid)
Role: Subscriber • Area: Collaborate/Invites

Steps

  1. Logout.
  2. Login as subscriber2 / subscriber123.
  3. Open Collaborate.
  4. In “Invited”, find the draft and click Accept invite.

Expected results

  • Draft moves to “Collaborating”.
  • Owner receives an “accepted invite” notification.
SUB-07 Create a suggestion (Sid)
Role: Subscriber • Area: Suggestions

Steps

  1. As Sid, open the draft (Open button in Collaborate or from Inbox summary).
  2. In Suggestions, use “Create suggestion” to propose a change to description.
  3. Provide a meaningful proposed value and submit.

Expected results

  • Suggestion appears as Open.
  • Timeline logs “Suggestion created”.
  • Owner receives Inbox notification.
SUB-08 Comment on the suggestion (Sid)
Role: Subscriber • Area: Suggestion discussion

Steps

  1. Select the open suggestion.
  2. In “Discussion”, add a comment clarifying the intent.

Expected results

  • Comment appears immediately.
  • Timeline logs “New comment”.
  • Owner receives Inbox update.
SUB-09 Owner applies the suggestion (Sam)
Role: Subscriber • Area: Owner review/apply

Steps

  1. Logout; login as subscriber1 (Sam).
  2. Open the draft.
  3. Select Sid’s open suggestion.
  4. Add an optional review note.
  5. Click Apply.

Expected results

  • Draft field updates to the proposed value.
  • Suggestion becomes Applied.
  • Timeline logs applied event.
  • Sid receives “Suggestion applied” notification.
SUB-10 Decline requires a note (negative)
Role: Subscriber • Area: Validation/Guardrails

Steps

  1. As Sam (owner), select an Open suggestion.
  2. Try to click Decline without entering a review note.
  3. Then enter a note and decline.

Expected results

  • Decline is blocked/disabled until a note exists.
  • Once declined, status becomes Declined and timeline logs it.
SUB-11 Watch / Watching and Inbox updates
Role: Subscriber • Area: Watch + Notifications

Steps

  1. Login as Sid (subscriber2).
  2. Open the draft and click Watch (confirm it becomes “Watching”).
  3. Logout; login as Sam (subscriber1).
  4. Make an owner edit to any field.
  5. Logout; login as Sid and open Inbox.

Expected results

  • Sid receives an “Owner edit” notification in Inbox.
  • Inbox item can open the draft directly.
SUB-12 Promote to ReadyToSubmit and submit to Moderator review
Role: Subscriber • Area: Workflow stages

Steps

  1. Login as Sam (owner).
  2. From Collaborate stage, click Ready to Submit.
  3. Go to Submit step and click Submit to Moderator review.

Expected results

  • Draft status becomes SubmittedForReview.
  • Timeline logs stage transition and submission event.
  • Danger zone actions are locked/blocked after submission.

5) Feature scripts (tab-by-tab)

These tests validate each top-level tab independently. They can be run in any order, but the best practice is: Search → Reader → Propose → Collaborate → Inbox → Review.

5.1 Home (Landing)

HOME-01 Always lands on Home (Vercel)
Area: Landing

Steps

  1. Open the Vercel URL in a fresh tab.

Expected

  • You see the Home/Landing page.

5.2 Search (filters, sort, hide, favourites)

SEARCH-01 Search keyword + clear
Area: Search

Steps

  1. Open Search.
  2. Type a keyword that exists in a title/description (example: “Context”).
  3. Confirm results change.
  4. Click Clear.

Expected

  • Results filter based on the keyword.
  • Clear resets filters/search.
SEARCH-02 Sort modes
Area: Search

Steps

  1. In Search, change Sort: Relevance → Recency → Popularity → Title (A–Z).
  2. Observe ordering changes.

Expected

  • Ordering updates appropriately for each sort mode.
SEARCH-03 Filters: Author / Category / Featured
Area: Search

Steps

  1. Pick an Author filter (not “All”).
  2. Pick a Category filter (not “All”).
  3. Enable “Featured only”.
  4. Confirm results change each time; then Clear.

Expected

  • Only matching cards show for each filter.
SEARCH-04 Not interested (hide) + undo + Hidden list
Area: Search

Steps

  1. On any card, open the “…” menu and click Not interested.
  2. Observe it disappears from Search.
  3. Click Undo on the toast to restore.
  4. Hide again; open Hidden (#); click Unhide.

Expected

  • Hide removes item from Search feed.
  • Undo restores immediately.
  • Hidden modal allows restoring items.

5.3 Favourites

FAV-01 Add to favourites and open from Favourites

  1. From Search, click Add to Favourites on a principle.
  2. Open Favourites.

6) End-to-end scenarios

E2E-01 Draft → Invite → Suggest → Apply → Submit → Moderator oversight
Actors: Sam, Sid, Moderator

Steps

  1. Sam creates a draft and opens it to collaborator requests.
  2. Sam invites Sid.
  3. Sid accepts invite and creates a suggestion + comment.
  4. Sam applies the suggestion.
  5. Sam marks ReadyToSubmit and submits to Moderator review.
  6. Moderator validates the draft is visible in Review → Drafts and opens timeline.

Expected

  • Inbox notifications appear for invite, suggestion, comment, apply, and submission.
  • Timeline reflects the full collaboration history.
  • Draft is locked appropriately after submission.

7) Negative / edge tests

Use this section to validate guardrails, permissions, and error prevention behaviors.
NEG-01 Non-subscriber cannot access Collaborate/Tools
Role: Non-subscriber • Area: Permissions

Steps

  1. Login as Non-subscriber.
  2. Attempt to open Collaborate and Tools.

Expected

  • Locked messaging appears; no collaboration/tools actions are accessible.
NEG-02 Owner cannot create suggestions (collaborators only)
Role: Subscriber (Owner) • Area: Guardrails

Steps

  1. As Sam (owner), open draft and go to Suggestions.
  2. Verify the “Create suggestion” panel is not shown to owner.

Expected

  • Owner cannot create suggestions; only collaborators can.
